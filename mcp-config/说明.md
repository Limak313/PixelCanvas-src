# PixelCanvas MCP 配置片段（人工留档，不会被自动加载）

本目录只是给人看/留档的独立配置文件，**Trae CN 不会扫描或加载这个目录**。

## 如何被引用

把本目录 `pixelcanvas.json` 里 `mcpServers.pixelcanvas` 这一项合并进 Trae CN 实际读取的单文件配置：

- 项目级：`<项目根>\.trae\mcp.json`（须先在 设置 > MCP 打开「启用项目级 MCP」）
- 用户级：`C:\Users\LXK\AppData\Roaming\Trae CN\User\mcp.json`

或在 Trae 的 设置 > MCP > 添加 > 手动添加 中粘贴该片段。保存后重载窗口或新开会话才会加载。

## 配置内容说明

- 类型：stdio（标准输入输出）本地 MCP 服务，不监听端口。
- 启动命令：包内 `runtime\dotnet.exe`，参数为包内 `server\PixelCanvas.Mcp.dll` 绝对路径。
- 输出根目录为部署包内 `output`；程序会自动添加 `PNG`、`工程` 或 `动画` 子目录，不能将根目录设置为 `PNG` 子目录。新版 `tools/list` 返回 8 个分组入口。
- 本文件中的 `${PACKAGE_ROOT}` 是占位符，粘贴到实际配置前需替换为部署包解压后的绝对路径（反斜杠需转义为 `\\`）。更省事的做法是在部署包目录内运行 `生成客户端配置.ps1`，它会按本机实际路径生成 `mcp-config.json`，无需手工替换。

## 为什么不能“一个 server 一个 json”

Trae CN 的 MCP 管理器只按**单一文件 URI** 读取并监听配置（`scanMcpServers(resource)` → 取文件里的 `mcpServers` 对象），没有目录扫描逻辑：

- 项目级 resource = `joinPath(workspaceFolder, ".trae", "mcp.json")`
- 用户级 resource = `joinPath(userSettingsResource, "..", "mcp.json")`
- 依据：安装目录 `D:\trae\Trae CN\resources\app\out\vs\workbench\workbench.desktop.main.js` 中的 MCP 管理器实现；官方文档 https://docs.trae.cn/ide/add-mcp-servers 也只描述单文件 `mcpServers` 写法。
